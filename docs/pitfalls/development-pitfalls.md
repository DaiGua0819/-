# XVI 开发踩坑与注意事项

本文档记录已经验证或从原始方案中提前识别的风险。新增问题必须包含“现象、根因、修复、预防”四部分。

## P-001：不要从现成小红书爬虫整体 Fork

- **状态**：已确认的设计约束
- **现象**：现成项目可能同时包含私有接口、互动操作、Cookie 文件、stealth、代理或验证码逻辑。
- **原因**：平台适配代码和不合规能力通常混在一起，难以证明企业项目的行为边界。
- **处理**：采用 clean-room 设计，只借鉴通用工程思想；平台代码独立放在 `SourceAdapter` 中。
- **预防**：依赖黑名单、许可证扫描、禁止字符串扫描和代码审查必须进入 CI。

## P-002：不能把 Cookie 导出当作登录方案

- **现象**：将 Cookie 写入 JSON、数据库或 Artifact，便于重新登录。
- **风险**：泄露账号会话，产生跨机器回放和审计风险。
- **处理**：使用 `launch_persistent_context(user_data_dir=...)` 保存正常浏览器 Profile；只允许人工登录。
- **预防**：禁止调用 `storage_state(path=...)`；禁止持久化 Cookie 字段；扫描 `cookies()` 和 `storage_state`。

## P-003：不能把选择器失败当成无结果

- **现象**：页面结构变化后，程序返回 0 条搜索结果。
- **原因**：核心 Locator 失效，但业务层误把空列表当作成功。
- **处理**：将核心选择器数量异常、不可见或超时统一映射为 `SELECTOR_DRIFT`。
- **预防**：Selector Registry 版本化；每次运行记录选择器版本；使用 Fixture 和 Smoke Test。

## P-004：轮播截图可能无限循环

- **现象**：下一张按钮持续可点击，程序不断重复截图。
- **原因**：没有检测首帧回环、Hash 重复或最大帧数。
- **处理**：使用最大帧数、pHash、首帧回环检测和“画面必须变化”检查。
- **预防**：每次点击都设置超时；连续不变化只允许有限重试；超过硬上限立即 `CAPTURE_INCOMPLETE`。

## P-005：不要通过图片 URL 获取原图

- **现象**：从 `src`、`srcset`、页面状态或网络响应中提取 CDN 图片地址，再用 HTTP 下载。
- **原因**：这绕过了“渲染区域截图”的访问边界，并可能涉及签名 URL 和私有资源。
- **处理**：只对可见图片元素或图片容器调用 `locator.screenshot()`。
- **预防**：代码扫描 `page.on("response")`、`requests` 图片下载、`srcset` 提取和原图 URL 字符串。

## P-006：Profile 并发会损坏浏览器状态

- **现象**：两个任务同时打开同一个 Profile，出现锁冲突、页面错乱或会话损坏。
- **原因**：只有应用层判断，没有本机锁和数据库租约。
- **处理**：文件锁 + 数据库租约 + 心跳；同一 Profile 队列并发为 1。
- **预防**：增加并发冲突测试；进程退出时释放租约；不能删除 Chromium lock 文件强行恢复。

## P-007：外部视觉模型可能造成数据出域

- **现象**：图片直接上传到第三方模型 API，但没有确认数据授权、日志和训练政策。
- **原因**：视觉模型调用被误认为普通 API 调用。
- **处理**：设置 `VISION_PROVIDER_MODE`；外部 Provider 必须经过审批；默认关闭数据出域。
- **预防**：不把来源 URL、作者信息或页面 HTML 传给模型；请求日志不记录图片和 Base64；使用 Secret Manager。

## P-008：视觉模型失败不应重新抓取来源

- **现象**：模型超时后，任务重新打开小红书并再次截图。
- **原因**：采集和视觉处理没有解耦，重试边界设计错误。
- **处理**：保存临时资产引用和采集状态；VisionProvider 独立重试；模型失败进入 `MODEL_UNAVAILABLE`。
- **预防**：重试任务只接收资产或笔记 ID，不重新调用 SourceAdapter。

## P-009：原始帧删除后历史重跑能力会下降

- **现象**：`ephemeral_only` 清理后无法使用新模型重新分析。
- **原因**：最小化保存策略与历史重跑能力存在取舍。
- **处理**：在 UI 和文档中显示当前可重跑范围；需要保留时单独审批内部缩略图或批准的原始帧保留。
- **预防**：保存资产处理策略、过期时间、模型输入版本和删除结果。

## P-010：不能用固定延迟伪装人类

- **现象**：通过随机等待、随机滚动和随机轨迹规避平台限制。
- **原因**：将稳定性节奏误用为反检测手段。
- **处理**：只使用有界、可解释的等待条件，例如元素可见、图片稳定和内容变化。
- **预防**：禁止 stealth、fingerprint、proxy-rotator 和 captcha-solver 依赖。
