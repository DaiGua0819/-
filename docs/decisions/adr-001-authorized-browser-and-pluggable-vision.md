# ADR-001：采用授权浏览器渲染截图与可插拔视觉模型

- **状态**：Accepted（图片保存策略由 ADR-002 补充）
- **日期**：2026-08-11
- **决策人**：项目组待补充
- **关联需求**：FR-001、FR-003、FR-005、FR-007
- **取代决策**：原始规格中“自训练视觉模型作为第一阶段主流程”的默认假设

## 1. 背景

项目需要获取小红书中能够体现品牌线下门店、陈列、快闪空间、装置和品牌专区的视觉内容。当前首要风险不是模型精度，而是来源访问的合规性、网页结构变化、Profile 并发、轮播完整性和图片资产治理。

原始规格中包含 DINOv2、图片分类头、LightGBM、Label Studio 和 MLflow 等完整训练闭环。经过方案调整，决定先验证授权浏览器采集链路，并允许直接接入已有视觉模型，以减少第一阶段的训练成本和返工风险。

## 2. 决策内容

### 2.1 来源采集

采用官方 Playwright Python Async API，通过独立的持久化浏览器 Profile 执行正常网页可见操作：

- 人工登录；
- 可见搜索框输入检索词；
- 有限滚动；
- 打开可见候选笔记；
- 切换可见轮播控件；
- 截取浏览器已经渲染的图片区域。

禁止使用私有接口、隐藏页面状态、网络响应解析、图片 CDN 直接下载、Cookie 导出、stealth、指纹伪造、代理轮换、验证码破解以及社交写操作。

### 2.2 视觉模型

使用 `VisionProvider` 抽象视觉模型，支持 Mock、企业内部模型和经过审批的外部模型。第一阶段不以自训练模型为前置条件。

视觉模型输出必须经过 JSON Schema 校验，并记录：

- Provider 名称；
- 模型名称和版本；
- Prompt 版本；
- 输入图片索引；
- 结构化结果；
- 调用时间和错误状态。

### 2.3 资产保存

默认采用 `ephemeral_only`：渲染帧只在分析和必要的故障诊断期间保留。是否保存内部缩略图必须由单独的数据、版权和合规政策决定。

## 3. 备选方案

### 方案 A：Fork 现成小红书爬虫

不采用。现成项目可能包含互动功能、私有接口、Cookie 文件、stealth、代理或不适合企业使用的许可证，难以证明行为边界。

### 方案 B：调用私有接口或请求签名

不采用。该方案绕过网页可见交互，增加平台、合规、安全和维护风险，也不符合项目访问边界。

### 方案 C：直接下载 CDN 原图

不采用。第一阶段只允许浏览器渲染区域截图，不保存原始 CDN URL，也不通过网络请求获取原图。

### 方案 D：先训练自有视觉模型

暂不采用为第一阶段前置条件。训练闭环可以在获取真实数据和人工反馈后再评估。

### 方案 E：只接入一个固定视觉模型

不采用。将模型名称写死会增加替换成本，且不同 Provider 的隐私、成本、上下文能力和输出稳定性不同。

## 4. 结果与影响

### 正面影响

- 先解决高风险采集链路，降低整体返工；
- 视觉模型可以快速替换；
- 不需要等待大规模标注数据；
- 浏览器采集与模型服务解耦；
- 便于用 Mock Provider 做本地测试；
- 原始帧短期保存，降低数据风险。

### 负面影响

- 外部视觉模型可能产生调用成本和数据出域风险；
- 模型结果不一定稳定，需要 Schema 校验、重试和人工复核；
- 没有自训练模型时，品牌和场景判断可能需要较高灰区比例；
- 删除原始帧后，新模型历史重跑能力受限。

## 5. 约束与执行规则

1. `SOURCE_ACCESS_MODE` 默认必须是 `disabled`。
2. `authorized_browser` 必须存在有效审批记录。
3. 同一 Profile 并发只能为 1。
4. 真实平台 Live Smoke Test 不能进入普通 CI。
5. 选择器失败必须是 `SELECTOR_DRIFT`，不能伪装成 0 结果。
6. 登录挑战和安全验证必须停止，不允许自动绕过。
7. VisionProvider 失败不能触发重新访问来源。
8. 所有新增技术方案必须更新本 ADR 或新建 ADR。

## 6. 后续复评条件

出现以下情况时，重新评估是否引入自训练模型：

- 外部视觉模型成本超过业务预算；
- 外部模型在关键场景上持续误判；
- 已积累足够确认标签和活动级数据；
- 数据出域限制不允许使用外部 Provider；
- 需要稳定的离线批量推理或本地化部署。
