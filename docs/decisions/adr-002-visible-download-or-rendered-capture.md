# ADR-002：可见下载优先、渲染区域截图兜底

- **状态**：Accepted
- **日期**：2026-08-11
- **关联需求**：FR-005、FR-006、FR-008、NFR-005、NFR-007
- **关联决策**：ADR-001

## 1. 背景

业务希望第一阶段尽可能保存小红书笔记中的“原图”。但系统的来源访问边界是授权浏览器中的正常网页可见操作，不能通过页面隐藏状态、网络响应或图片 CDN 地址绕过页面交互。因此，“原图”不能被定义为任意方式取得的最高分辨率文件，而只能定义为页面向当前授权用户提供的可见下载结果。

同时，部分页面可能没有可见下载按钮，或者下载动作在当前页面状态下失败。为了不因下载入口差异导致整个采集链路不可用，需要一个可审计的渲染区域截图兜底方案。

## 2. 决策

采集每个轮播帧时按以下顺序执行：

1. 定位页面上当前可见的下载按钮；
2. 使用 Playwright `page.expect_download()` 等待并捕获该可见按钮触发的浏览器下载；
3. 对下载文件进行图片解码、尺寸、格式、SHA-256 和 pHash 校验；
4. 如果没有可见下载按钮，或可见按钮没有在超时时间内产生浏览器下载，则对当前可见的轮播渲染区域调用 `locator.screenshot()`；
5. 对截图执行同样的图片校验和 Hash 记录；
6. 使用 `capture_method=visible_download` 或 `capture_method=rendered_screenshot` 写入资产元数据。

可见下载文件和渲染截图都只进入受控临时资产目录，并通过运行 ID、笔记 ID、源顺序和 Hash 关联。系统不保存原始 CDN URL，不读取 `src`/`srcset`，不监听或解析网络响应，不自行重放下载请求。

## 3. “原图”的准确含义

在本系统中：

- `visible_download`：页面可见下载入口提供的文件，属于第一阶段允许保存的原图候选；
- `rendered_screenshot`：浏览器已渲染区域的截图，不宣称为原始文件；
- 如果可见下载失败而截图成功，运行结果必须保留实际的 `capture_method`，不能把截图标记为原图；
- 如果下载和截图都失败，当前帧失败，不能使用隐藏接口或 CDN 请求补齐。

因此，第一阶段可以满足“优先下载原图”的目标，但不能承诺所有页面、所有账号和所有笔记都能取得平台原始文件。

## 4. 备选方案

### 方案 A：读取 `img.src` 或 `srcset` 后直接请求

不采用。该方式绕过用户可见下载动作，可能直接访问 CDN 或签名资源，违反访问边界。

### 方案 B：监听网络响应并保存图片响应体

不采用。网络响应解析属于禁止的隐藏数据获取方式，也会使页面行为和资源权限难以审计。

### 方案 C：始终使用截图

不采用。截图会损失页面提供的原始文件能力，不能满足优先保存可见下载结果的业务目标。

### 方案 D：可见下载失败后改用隐藏接口重试

不采用。失败只能按有限超时降级为渲染区域截图，不能扩大访问权限。

## 5. 运行与保留规则

- 默认真实来源访问仍为 `SOURCE_ACCESS_MODE=disabled`；真实运行必须经过授权浏览器和人工在场审批。
- 原始资产只作为受控临时文件保存，保留期限由 `RAW_ASSET_TTL_HOURS` 控制；长期保存需要单独的数据、版权和合规审批。
- Artifact 只记录采集方式、尺寸、格式、Hash、索引、状态和脱敏运行信息，不记录 Cookie、Authorization、验证码或原始 CDN 地址。
- 轮播通过首帧回环、pHash 重复、下一张后的画面变化和最大帧数共同判断结束；无法确认完整遍历时必须标记为不完整。

## 6. 验收标准

- Fixture 中可见下载按钮产生的 PNG 能被 Pillow 解码并保存；
- 无下载按钮时，渲染区域截图可以保存并通过图片校验；
- 每个资产均记录准确的 `capture_method`、尺寸、格式、SHA-256 和 pHash；
- 不存在 `src`/`srcset` 提取、网络响应解析或直接 CDN 请求代码；
- 下载失败不会触发隐藏接口重试；
- 每次运行生成 `manifest.json`、`steps.jsonl` 和 `result.json`。

## 7. 后续复评条件

当业务明确需要长期保留原始下载文件、跨模型历史重跑或对外分发时，必须重新评估版权、平台规则、数据保留期限和存储权限，并通过新的 ADR 扩展保留策略。
