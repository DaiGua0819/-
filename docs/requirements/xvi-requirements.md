## 1. 当前确认结论

本项目第一阶段优先实现“授权浏览器采集”能力：通过独立的持久化浏览器 Profile，在取得企业审批后，使用正常网页可见界面搜索小红书内容、打开笔记、遍历轮播并保存图片。图片采集优先使用页面上用户可见的下载入口触发浏览器下载；没有可见下载入口时，保存浏览器已经渲染的完整图片区域。两种方式均不得读取隐藏状态、解析网络响应或直接请求 CDN。

视觉分析不以前置自训练为条件。第一阶段使用可插拔的 `VisionProvider`，可以连接企业内部视觉模型、经审批的外部视觉模型或 Mock Provider。后续是否引入 DINOv2、轻量分类器、LightGBM 或人工训练流程，根据真实数据和外部视觉模型表现决定。

## 2. 产品目标

1. 根据品牌、别名、地点和事件关键词生成检索任务。
2. 在授权模式下通过网页可见操作发现候选笔记。
3. 打开候选笔记并逐张采集可见轮播图片区域。
4. 保留图片顺序、来源链接、采集时间、运行证据和完整性状态。
5. 对采集结果调用可替换视觉模型，输出严格 JSON 的图片级和笔记级判断。
6. 为后续人工复核、飞书投影、模型评估和业务检索提供稳定数据基础。
7. 所有任务可暂停、重试、审计、清理和追溯。

## 3. Phase 1 范围

### 3.1 必须实现

- 浏览器 Profile 创建、隔离和人工登录。
- Profile 文件锁和数据库租约。
- 来源访问策略和审批校验。
- 搜索词提交、有限滚动和候选收集。
- URL 规范化和候选幂等去重。
- 候选笔记打开和关闭。
- 轮播图片区域定位。
- 优先通过页面上用户可见的下载入口触发浏览器下载；没有下载入口时保存浏览器渲染图片区域。
- 图片顺序、尺寸、Hash、采集方式和临时资产记录。
- 最大结果数、滚动次数和图片数限制。
- 登录失效、挑战页面、选择器漂移和页面异常检测。
- 运行 Manifest、Steps、Result 和诊断 Artifact。
- Mock/本地 Fixture 浏览器测试。
- 可选的 VisionProvider 调用和严格 JSON 校验。
- 默认短期保存并清理原始渲染帧。

### 3.2 Phase 1 明确不做

- 点赞、收藏、评论、关注、私信、发帖等写操作。
- 评论区、作者画像、粉丝关系和无关个人信息采集。
- 小红书私有接口、隐藏页面状态、请求签名或网络响应解析。
- 通过隐藏接口、网络响应、页面私有状态或直接 CDN 请求下载图片。
- stealth、指纹伪造、代理轮换、验证码破解或安全挑战自动处理。
- 无限滚动、多账号批量扩容和绕过平台限制。
- 以自训练模型为上线前置条件。
- 自动 A/B 发布和自动同步飞书业务表。
- Label Studio、MLflow、主动学习和复杂模型治理闭环。

## 4. 来源访问与安全要求

默认配置必须为：

```dotenv
SOURCE_ACCESS_MODE=disabled
CAPTURE_MODE=visible_download_or_rendered
ALLOW_VISIBLE_DOWNLOAD=true
ALLOW_NETWORK_EXTRACTION=false
ALLOW_SOCIAL_WRITE_ACTIONS=false
ALLOW_STEALTH=false
ALLOW_CAPTCHA_BYPASS=false
ALLOW_COOKIE_EXPORT=false
ALLOW_RAW_IMAGE_PERSISTENCE=false
```

允许的来源模式：

- `disabled`：完全禁止真实来源访问。
- `manual_import`：仅处理企业批准的图片包或链接。
- `authorized_browser`：存在有效审批记录时，允许正常网页浏览和渲染区域截图。

`authorized_browser` 必须同时满足：全局模式允许、Profile 有效、审批未过期、Profile 未暂停、当前运行成功获取租约。

## 5. 功能需求

### FR-001 Profile 管理

系统必须支持独立 Profile、人工登录、登录状态探测、Profile 暂停和 Profile 级并发限制。系统不得保存 Cookie 字段或提供 Profile 下载接口。

### FR-002 检索任务

系统必须支持保存检索词、标签、方向标签、Profile、最大结果数、最大滚动次数和启停状态。第一阶段优先从用户指定的飞书 Base 读取查询配置，支持手动运行一次，定时调度后置。飞书读取失败时不得静默使用空查询。

### FR-003 候选发现

系统必须通过页面可见搜索框提交查询，收集可见结果的规范化链接、可见标题、可见发布时间提示和结果排名。选择器失效不得被解释为“无结果”。

### FR-004 笔记打开

系统必须记录候选笔记打开过程、页面上下文、选择器版本、打开失败原因和运行耗时。遇到登录或挑战页面时立即停止。

### FR-005 轮播采集

系统必须通过可见轮播区域逐张截图，保存源顺序，识别首帧循环、重复帧、无法前进、加载失败和未完整遍历。单个笔记必须有最大帧数和总时限。

### FR-006 图片资产

系统必须记录图片临时 URI、尺寸、格式、SHA-256、pHash、采集索引、所属笔记、过期时间和采集状态。不得记录原始 CDN URL。

### FR-007 视觉模型

系统必须通过 `VisionProvider` 接口调用视觉模型。模型请求和响应必须版本化，响应必须通过 JSON Schema 校验。模型不可用时不得重新访问来源。

### FR-008 运行 Artifact

每次浏览器运行必须生成 `manifest.json`、`steps.jsonl`、`result.json` 和必要的脱敏诊断文件。Artifact 不得包含 Cookie、Authorization、验证码、二维码或完整个人资料。

### FR-009 审计与清理

所有来源访问、登录状态变化、截图、模型调用、失败、取消和清理动作必须可关联到运行 ID。临时帧必须按 TTL 清理，清理过程需要有结果记录。

## 6. 非功能需求

| 编号 | 要求 |
|---|---|
| NFR-001 | 同一 Profile 同时最多一个活跃浏览运行 |
| NFR-002 | 搜索结果、滚动次数、单笔记图片数和运行时长均有硬上限 |
| NFR-003 | 选择器失败不得静默产生空数据 |
| NFR-004 | 浏览器崩溃后任务可判定为可重试或永久失败，Profile 不得被破坏 |
| NFR-005 | 日志、数据库、Trace 和 Artifact 不得泄露 Cookie、Token、验证码或密码 |
| NFR-006 | 视觉模型调用失败不得导致重复访问来源 |
| NFR-007 | 原始帧默认只在推理和故障诊断所需的最短期限内保存 |
| NFR-008 | 真实来源 Live Smoke Test 不进入普通 CI |
| NFR-009 | 所有阈值、超时、保留期限和功能开关来自配置 |
| NFR-010 | 后台数据是事实源，未来飞书只能作为可重建投影 |
